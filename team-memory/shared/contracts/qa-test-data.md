# QA 测试数据协议

## 1. 命名规则

可由用户看到的测试记录使用：

`<suite>-<case>-<account>-<yyyymmdd>-<run-short-id>`

例如：`S5-ROLE-alice-20260810-a7c9`。字段使用 ASCII 字母、数字和连字符；受长度限制时优先保留 suite、account、日期和 run short id。

## 2. 数据清单

每条写入必须记录：`runId`、caseId、账号/角色、租户、标题、业务 ID/编号、创建方式、创建时间、最终状态和保留策略。密码、令牌和 Cookie 不属于测试数据清单。

## 3. 真实数据库规则

- 默认禁止写入真实/共享数据库；执行前必须记录用户或环境所有者的明确授权。
- 只能通过测试范围要求的入口写入。要求 UI 验收时，禁止用 API/SQL 绕过 UI 造数或修改状态。
- 不修改既有非 QA 数据，不复用无法确认归属的数据，不通过自审或越权绕过业务规则。
- 失败后保留已创建草稿和业务锚点，以便诊断与恢复；不得自动清理掩盖问题。

## 4. 保留与清理

- 默认策略为 `preserve`，报告中说明数据可见范围和最终状态。
- 清理属于独立的破坏性操作，必须获得明确授权，先列出精确业务 ID、数量和租户，再执行并记录结果。
- 禁止使用标题前缀通配删除、全表清理或删除未知来源数据。
- 并发运行不得共享同一标题或业务锚点；通过 `runId` 区分。

## 5. 恢复执行

恢复时先按清单核验业务 ID/编号、当前状态和部署环境。锚点仍有效则继续原流程；不一致时标记 `STALE_ANCHOR` 并停止写入，交由 team-lead 决定重建数据或重新开始运行。
